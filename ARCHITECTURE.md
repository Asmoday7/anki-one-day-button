# HoldUp: архитектура 0.4.4-dev

HoldUp создаёт виртуальное дополнительное назначение той же карточки.
Оригинал остаётся в reviewer для обычной оценки Anki/FSRS. Общий интерфейс
последовательно показывает штатные карточки и готовую практику.

## Инварианты

- Назначение и действия практики не вызывают answering API и не добавляют revlog.
- Нажатие HoldUp сохраняет дополнительный срок и оставляет обычный ответ открытым.
  Пользователь отдельно выбирает Again, Hard, Good или Easy. Только эта настоящая
  оценка продвигает оригинал и расходует дневной лимит новых карточек.
- Физические note/card не создаются. Одна карточка имеет одно дополнительное
  назначение; повторная запись заменяет его срок.
- Обычные действия практики не меняют queue, due, ivl, memory_state, reps, lapses
  и type оригинала. Возврат сохранённой собственной паузы — отдельная обратимая операция.
- Встроенный scheduler не изменяется. Прямых SQL-записей и пятого рейтинга нет.
- Повреждённые и неизвестные metadata не перезаписываются; чужие ключи сохраняются.

## Хранение и сроки

Новые назначения сохраняются публичным `col.set_config(..., undoable=True)` в
ключе `holdupPractice`, отдельно от полей карточек. Это принципиально для живого
reviewer: `update_card()` сбрасывает native-очередь, а случайный порядок повторений
после чтения карточки может пересобраться иначе. Тогда нажатие обычной оценки
отклоняется с `not at top of queue`. Простое повторное чтение очереди эту проблему
не решает. Запись собственного config не имеет флагов `card` или `study_queues` и
оставляет текущий native head и scheduling states пригодными для оценки.

Компактный формат:

```json
{"v":1,"cards":{"1234567890123":[1792300000000,120,false]}}
```

Три значения — абсолютный срок Unix milliseconds, интервал в секундах и признак
следующего учебного дня. В календарном режиме интервал 86400 номинальный; срок
определяет Anki. Проверяются версия, идентификаторы, типы, диапазоны и точность
времени до 2^53. Неизвестные схемы не перезаписываются. Собственные операции имеют
названия HoldUp и объединяются через публичный Undo API; обычные оценки остаются
отдельными операциями.

Сохранённые назначения из `Card.custom_data` продолжают читаться через
`find_cards("prop:cdn:odbat>=0")`: схемы 2/3 с ключами `odbv`, `odbat`, `odbsecs`,
`odbnext` и необязательным `odbq`. Новый срок из config имеет приоритет. Значение
`null` закрывает прежнее назначение, сохраняя исходные metadata нетронутыми;
Undo восстанавливает прежний срок. Полная миграция или переписывание карточек при
установке не выполняются. Только восстановление сохранённых пауз требует Card API;
обычная кнопка и практика не меняют карточку.

Config занимает примерно 50 байт на активное назначение и рассчитан на небольшой
список дополнительной практики. Anki передаёт config целиком при синхронизации:
это ограничение масштабирования для больших очередей. История разрешения конфликтов
между несколькими устройствами не реализована; последняя запись всего значения
может заменить другую. Экспорт отдельной колоды APKG не включает этот config;
проверенные гарантии переноса между устройствами не заявляются.

Фиксированный интервал ограничен 1..86400 секундами. Календарный режим читает
`col.sched.day_cutoff * 1000` в CollectionOp. Anki вычисляет ближайший `next_day_at`
по своим настройкам, часовому поясу и переходам времени. Просроченная граница
отклоняется до записи. Уже сохранённая дата не пересчитывается при смене настроек.

Package не мигрирует коллекцию. Существующие назначения с этим контрактом
сохраняются в карточках и доступны HoldUp. Add-on Manager config локален и привязан
к установленному пакету; автоматическое копирование настроек другой установки
не выполняется. В инструкции предусмотрены отключение другой копии и повторный
выбор интервала.

## Операции и Undo

Все записи проходят через сериализованный CollectionOp. Qt обновляется на главном
потоке; callbacks проверяют коллекцию и поколение. QueryOp возвращает снимок
назначений, доступности и дерева колод. Таймер примерно раз в секунду только читает
данные и обновляет индикаторы; он не начинает изучение и не прерывает карточку.

Обычная отметка записывает только собственный config с reviewer как initiator.
Пересборка native-очереди и переприсваивание её начала не выполняются. Назначение,
повтор, завершение и пакетная очистка поддерживают штатный Undo/Redo. При пакетной
операции все ожидаемые записи проверяются до первой записи. Клик во время фонового
чтения принимается один раз и сериализуется CollectionOp после чтения. Локальная настройка
интервала не является Undo карточки. Undo/Redo повтора и завершения обновляют
показ в reviewer после `operation_did_execute`, даже когда config не требует
пересборки native-очереди.

При Undo последнего переноса или завершения с overview готовая практика снова
открывается в reviewer через защищённый переход после загрузки congrats.
Отмена со страницы колод только обновляет индикаторы. Область практики и её
счётчиков берётся из `deck_and_child_ids(get_current_id())`: `decks.active()`
может ещё описывать предыдущую колоду до пересборки native-очереди.

Назначение HoldUp и обычная оценка — отдельные Undo-операции. После последовательности
HoldUp → native rating первый Undo отменяет только native rating и возвращает
оригинал; сохранённый срок практики остаётся. Следующий Undo отменяет назначение,
если не было другого действия с коллекцией. Undo повтора или завершения практики
меняет только metadata практики и не отменяет предыдущую обычную оценку.

При фактической обычной оценке ReviewFlow сохраняет глубокую копию её V3 scheduling
states и context. После Undo восстановленная backend-очередь может начинаться с
другой карточки обучения, срок которой только что наступил. Перед показом оригинала
в GUI сохранённый снимок проверяется по `reps`, `queue`, `type`, `due` и колоде
восстановленной карточки в базе. При совпадении оригинал показывается с его states
и context раньше общей очереди; backend-очередь не переставляется и не изменяется.
Готовая практика не подменяет возвращённый оригинал. Отслеживание Undo/Redo
использует счётчики операций и названия операций, сформированные самой Anki.

После Undo открытого ответа кнопка получает свежий одноразовый токен. Двойные клики
и устаревшие команды не могут повторить действие на другой карточке.
Callback перехода между экранами выполняется после `operation_did_execute` через
`QTimer.singleShot(0, ...)`, чтобы избежать двойной загрузки страницы завершения.
Запрос высоты панели проверяет наличие документа и контекст webview.
Если обычный ответ отклонён внешним изменением очереди, после завершения callback
reviewer выходит из `transition` через настоящий native head. Оценка автоматически
не повторяется; ошибочный ответ не записывается повторно. Проверка выполняется
после двух событий Qt, чтобы успешный переход успел завершиться.

## Общий reviewer

Адаптируются GUI-методы reviewer; scheduler и native очередь сохраняются.
На переходе берётся реальная вершина Anki, а не произвольная карточка из коллекции.
Её срок сравнивается с ближайшим готовым назначением практики:

- Внутридневное обучение имеет Unix timestamp.
- Review и дневное обучение имеют учебную дату; используется начало этого дня.
- Новые позиции не являются временем: готовая практика может предшествовать им.

Нативный порядок очереди и её лимиты задаёт Anki. Практика ограничена выбранной
колодой и подколодами. Приостановленные, скрытые и filtered-deck карточки исключены.
Показ практики не имеет native scheduling states; guard блокирует обычные оценки,
клавиши 1–4, auto-answer и auto-advance для дополнительного показа.

При Undo native ответа возвращаемый оригинал имеет приоритет перед готовой
практикой. Ближайший дополнительный срок не может подменить эту карточку на переходе,
даже если срок наступил во время ответа или отмены. После явного обычного ответа
на возвращённый оригинал снова действует стандартное сравнение сроков.

В изучении зелёный счётчик — native review плюс готовая практика. Подпись
`HoldUp: ожидают N` показывает будущие назначения. В списке колод штатные три
числа остаются данными Anki; собственная метка `HoldUp · N` показывает только
готовую практику. Родители включают подколоды, поэтому сводные числа перекрываются.
Опрос обновляет собственные DOM-узлы без полной перезагрузки списка.

## Язык и сборка

`i18n.py` читает `anki.lang.current_lang`: русский для `ru`, `ru_RU` и `ru-RU`,
английский для остальных значений. Без Anki используется английский; импорт модели
не запускает GUI. Язык применяется после перезапуска Anki. Строки форматируются
отдельно от HTML, webview получает JSON с экранированием `<`, `>` и `&`.

`tools/package_addon.py` собирает разрешённый список runtime-файлов в корень ZIP.
Результат — `.dev/dist/holdup.ankiaddon`; публичная сборка —
`dist/holdup-0.4.4-dev.ankiaddon`. Тесты, кеши и пользовательские данные не пакуются.

## Проверки и ограничения

Автоматические проверки используют временные коллекции и профили. Они предназначены
для проверки сохранения расписания/FSRS/revlog, обычных оценок, дневного лимита,
сроков, Undo/Redo, установки ZIP, двух языков, меток и геометрии интерфейса.
GUI-прогоны выполняются последовательно. Пропуск теста не подтверждает интеграцию.

Дополнительно проверяются полная отмена/восстановление смешанных историй с
новыми, изучаемыми, повторяемыми и переучиваемыми карточками, другая оценка после
Undo, быстрые парные Undo/Redo, возврат практики с overview и повторное назначение
при новом обычном показе той же карточки. На каждом шаге сравниваются расписание,
FSRS memory state, история, назначения и штатные счётчики.

Приватные GUI API требуют проверки при обновлении Anki. Windows/Python 3.13,
реальная синхронизация между устройствами, сложные шаблоны и аудио требуют ручной
проверки. AnkiDroid не выполняет этот Python-аддон. При конфликтах синхронизации
последняя запись config может заменить другую; гарантия разрешения конфликтов
без отдельного тестирования не заявляется. Практика не передаёт оценку в FSRS,
хотя влияет на реальную память и последующие ответы пользователя.
